Before video playback will work on a physical device, each platform needs a small amount of one-time configuration. On iOS you need to edit `Info.plist` (or use Xcode's Capabilities UI) to allow network video, background audio, and PiP. On Android the plugin handles most setup automatically through its own manifest, but you still need to declare the `INTERNET` permission and set the minimum SDK version. This page covers every required and optional entry for both platforms.

## iOS Setup

Flutter's build system handles CocoaPods and Swift Package Manager automatically — you do not need to run `pod install` manually or add any `Package.swift` entries. Just add the package to `pubspec.yaml` and run `flutter pub get`.

<Tabs>
  <Tab title="Info.plist (Manual)">

Open `ios/Runner/Info.plist` in a text editor or Xcode's property list editor and add the keys below.

**Network access for HTTP video URLs**

Without this entry, AVFoundation will refuse to load plain HTTP (non-HTTPS) URLs. HTTPS URLs work without it, but many test streams and CDNs use HTTP.

```xml
<key>NSAppTransportSecurity</key>
<dict>
    <key>NSAllowsArbitraryLoads</key>
    <true/>
</dict>
```

<Warning>
  `NSAllowsArbitraryLoads` disables Apple's App Transport Security globally. For production apps consider using `NSExceptionDomains` to allow only the specific domains you need instead of opening all HTTP traffic.
</Warning>

**Background audio and Picture-in-Picture**

The `audio` string is **required** for background audio and AirPlay. Adding `picture-in-picture` is **optional but recommended** — it enables automatic PiP when the app moves to the background (iOS 14.2+).

```xml
<key>UIBackgroundModes</key>
<array>
    <string>audio</string>
    <string>picture-in-picture</string>
</array>
```

**Chromecast local network discovery (iOS 14+ only)**

The plugin's `CastDeviceDiscovery` uses the system Bonjour browser to find Cast devices. iOS 14 and later require an explicit usage description and the `_googlecast._tcp` Bonjour service entry, or the first mDNS scan will fail silently.

```xml
<key>NSLocalNetworkUsageDescription</key>
<string>Used to find Cast devices on your local network.</string>
<key>NSBonjourServices</key>
<array>
    <string>_googlecast._tcp</string>
</array>
```

<Note>
  The Local Network permission prompt appears the first time `CastDeviceDiscovery.discover()` is called. If you do not use Chromecast, you can omit these two keys entirely.
</Note>

  </Tab>
  <Tab title="Xcode Capabilities (Alternative)">

If you prefer a GUI, Xcode's Capabilities panel will write the `UIBackgroundModes` entries for you:

1. Open `ios/Runner.xcworkspace` in Xcode.
2. Select the **Runner** target in the project navigator.
3. Open the **Signing & Capabilities** tab.
4. Click **+ Capability** and add **Background Modes**.
5. Check **Audio, AirPlay, and Picture in Picture**.

Xcode writes both `audio` and `picture-in-picture` to `Info.plist` automatically. You still need to add the `NSAppTransportSecurity` and Chromecast keys by editing `Info.plist` directly.

<Tip>
  Using the Capabilities panel is the recommended approach for App Store submissions because Xcode also generates the required entitlement file. The manual `Info.plist` approach is equivalent for local testing.
</Tip>

  </Tab>
</Tabs>

### Minimum Deployment Target

The plugin requires **iOS 12.0 or later**. Verify the setting in Xcode:

1. Select the **Runner** target → **General** tab.
2. Under **Minimum Deployments**, set **iOS** to `12.0`.

Or set it in `ios/Podfile`:

```ruby
platform :ios, '12.0'
```

### Feature Requirements Summary

| Feature | Required Info.plist key(s) | Minimum iOS |
|---------|-----------------------------|-------------|
| HTTP video URLs | `NSAllowsArbitraryLoads` | 12.0 |
| Background audio | `UIBackgroundModes → audio` | 12.0 |
| Picture-in-Picture | `UIBackgroundModes → audio + picture-in-picture` | 14.0 |
| Automatic PiP on backgrounding | Same as above | 14.2 |
| Chromecast discovery | `NSLocalNetworkUsageDescription` + `NSBonjourServices` | 14.0 |

## Android Setup

The plugin's own `AndroidManifest.xml` (inside the package) automatically declares the `MediaSessionService`, the `android:supportsPictureInPicture="true"` activity attribute, and the `FOREGROUND_SERVICE` permission. You only need to add the two entries below to your app.

### Internet permission

Add the permission to `android/app/src/main/AndroidManifest.xml`, before the `<application>` tag:

```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android">

    <uses-permission android:name="android.permission.INTERNET" />

    <application
        ...>
    </application>

</manifest>
```

### Minimum SDK version

ExoPlayer (Media3) requires API 24 (Android 7.0) or later. Set `minSdkVersion` in `android/app/build.gradle`:

```kotlin
android {
    defaultConfig {
        minSdk = 24
        // ...
    }
}
```

Or in `build.gradle` using Groovy syntax:

```groovy
android {
    defaultConfig {
        minSdkVersion 24
        // ...
    }
}
```

### What the plugin configures automatically

You do **not** need to add these yourself — the plugin's manifest merges them:

- `android:supportsPictureInPicture="true"` on the main activity
- `MediaSessionService` for lock-screen and notification controls
- `FOREGROUND_SERVICE` permission for background media notifications

### Picture-in-Picture on Android

Android PiP is powered by the [`floating`](https://pub.dev/packages/floating) package (included as a dependency). No additional `MainActivity` changes are needed.

<Note>
  On Android, PiP is only available when the video is in **Dart fullscreen mode** — that is, when a custom overlay is active via `overlayBuilder`. This ensures only the video surface is captured in the PiP window. Enter fullscreen first (`await controller.enterFullScreen()`) before calling `enterPictureInPicture()`. PiP requires Android 8.0+ (API 26+).
</Note>

## Troubleshooting

<Accordion title="HTTP videos are not playing on iOS">
  AVFoundation blocks plain HTTP URLs by default under App Transport Security. Add `NSAllowsArbitraryLoads` to `Info.plist` as shown in the iOS section above, or whitelist individual domains with `NSExceptionDomains`. Restart the app after editing `Info.plist` — a hot-reload is not sufficient.
</Accordion>

<Accordion title="PiP is not available on iOS">
  Check the following in order:

  1. Both `audio` **and** `picture-in-picture` must be present in `UIBackgroundModes` for PiP to work (`audio` alone is not sufficient for PiP).
  2. Use `await controller.isPictureInPictureAvailable()` to confirm PiP is supported at runtime — simulators often return `false`.
  3. The device must be running iOS 14.0+ for manual PiP; automatic PiP on backgrounding requires iOS 14.2+.
  4. The video must be **playing** before `enterPictureInPicture()` is called.
</Accordion>

<Accordion title="PiP is not available on Android">
  Android PiP has three requirements that must all be met simultaneously:

  1. Device must run Android 8.0+ (API 26+).
  2. The video must be in **Dart fullscreen mode** (custom overlay via `overlayBuilder`).
  3. `allowsPictureInPicture: true` on the controller (this is the default).

  Confirm via `await controller.isPictureInPictureAvailable()`. If it returns `false` outside fullscreen, that is expected behaviour — call `enterFullScreen()` first.
</Accordion>

<Accordion title="Background audio stops on iOS">
  Background audio requires:

  1. `UIBackgroundModes` must contain `audio` in `Info.plist` (the `picture-in-picture` entry is optional — it is only needed for PiP, not for background audio).
  2. In Xcode, **Target → Signing & Capabilities → Background Modes**, the checkbox **Audio, AirPlay, and Picture in Picture** must be checked.

  If Xcode shows the capability as unchecked, the entitlement may be missing even if `Info.plist` appears correct. Add the capability via Xcode to generate the entitlement file and then rebuild.
</Accordion>

<Accordion title="Chromecast discovery finds no devices">
  On iOS 14+, mDNS scans require the Local Network permission. Verify that:

  1. `NSLocalNetworkUsageDescription` and `NSBonjourServices → _googlecast._tcp` are present in `Info.plist`.
  2. The user has granted Local Network access when prompted (Settings → Privacy & Security → Local Network → your app).
  3. Your development device and the Chromecast are on the same Wi-Fi network.

  On other platforms, discovery uses a pure-Dart mDNS implementation and should work without additional permissions.
</Accordion>

<Accordion title="Video does not play on Android (no error shown)">
  1. Confirm `<uses-permission android:name="android.permission.INTERNET" />` is in your `AndroidManifest.xml`.
  2. Check that `minSdk` is set to at least `24` in `build.gradle`.
  3. Run `adb logcat` and filter for `ExoPlayer` to see detailed error messages from Media3.
  4. For HTTPS streams with self-signed certificates, add a `network_security_config.xml` to allow the specific domain.
</Accordion>
